# D06 gs24 후속 탐색 실험 결과

**Test-674 개발 평가의 관찰(gs24가 높음)을 바탕으로 제안한 후속 탐색 실험이다.** 사전 등록(`PREREGISTRATION.md`, 46ade76)대로 실행했다.
가중치·임계값은 Train calibration에서만 정했고 Test 결과로 조정하지 않았다. 이 실험의 Test-674 수치는 독립 검증이 아니며, 최종 성능은 독립 데이터로 검증해야 한다.

- 새로 학습: full28_noObfNew, full31_noHook (Train 외부 6셀 + Test 프로토콜 2 seed, 16모델, 7초). 나머지는 저장 점수 재사용.
- 검사: 재사용한 full35의 Train 외부 5% TP·FP = `fair_comparison.csv`, full35·gs24의 Test 5% TP·FP·mastra TP = `../d06_test674_dev` (assert).
- 결합 가중치 선택 결과(`eval/manifest.json`): Train 외부 C1 prob w(gs24)=0.5/0.0, C2 logit 0.4/0.2, C3 rank 0.4/0.2, C6 (JS 변경 w, JS 변경 없음 w) = (0, 1)/(0.2, 0.2).
  Test 프로토콜 seed09: C1 0.9, C3 1.0 / seed10: C1·C2·C3 모두 0.0(=full35).

## 1. 원인 확인 (목표 FPR 5%, TP / FP / HB 오탐)

| 모델 | Train 외부 split1 | split2 | Test seed09 (mastra) | seed10 (mastra) | Test PR-AUC |

- **Test-674에서 gs24가 높은 원인은 obfNew 7개 제거다.** obfNew만 빼도 mastra 62/113을 잡고 PR-AUC가 .928/.958로 오른다. 설치 훅 4개만 빼면 변화가 없다(mastra 8/22).
- 공격 유형 B(새 의존성) Recall: full35 8/25 → obfNew 제거 61/112, gs24 66/112 (Test, 114쌍). Train 외부 B 유형(52쌍)은 모든 모델이 42~44로 같다.
- **Train 외부에서는 obfNew 제거가 오히려 손해다**: split1 TP 854 → 827, C 유형(JS 변경 공격) 104/102 → 84/93. Train에는 mastra 유형이 거의 없고 obfNew가 C 유형 탐지에 기여한다.
- gs24는 Test seed10에서 canisterworm을 32쌍 놓쳤다(A 유형 78 → 44). obfNew 제거만 한 모델은 canisterworm을 모두 잡았으므로(68/68), 이 손실은 설치 훅 4개 제거와 함께 생긴다.

## 3. 해석

- 원인: **obfNew(새 버전 전체 난독화 통계)가 JS 변경이 없는 의존성 추가형 공격(mastra)에서 탐지를 억누른다.** 이것은 Test-674에서 본 관찰이고, Train에서는 같은 유형이 6쌍뿐이라 확인할 수 없다.
  반대로 Train 외부에서는 obfNew가 JS 변경 공격(C 유형) 탐지에 기여한다.
- "gs24의 탐지와 full35의 탐지를 결합하면서 오탐도 줄인다"는 **Train 기준으로는 확인되지 않았다**(사전 규칙 만족 결합 없음).
  Test에서는 C5(JS 변경 없음 & 새 의존성 & 설치 스크립트 추가 없음 → gs24)가 그 방향을 보이지만(손실 0, 신규 오탐 1/1, 5% mastra 68/114),
  Train에서 검증할 수 없는 영역에 대한 규칙이고 Test-674 관찰에서 출발했다.
- 제안: C5(또는 그 영역에서 obfNew를 쓰지 않는 모델)를 **독립 데이터 검증 대상 후보**로 등록한다. B3 최종 후보는 바꾸지 않는다.
  다음 데이터(D07 등)에 mastra 유형 악성이 들어오면 Train 내부에서 이 규칙을 다시 평가할 수 있다.
