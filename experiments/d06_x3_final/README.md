## 4. 판단

1. **full35+X3+D**: Train에서는 가장 좋다(3% Recall .919/.929·FPR .034/.036, PR-AUC .966/.972, HB FPR 5%에서 .167/.151로 full35보다 낮음).
   **Test에서는 개선이 없다**(5% Recall .486/.519 vs full35 .486/.565, mastra .10/.20). X3·D가 겨냥한 설치 훅·JS 변경 신호는 mastra(JS 변경·훅 없음)에 값이 없다.
2. **full28_noObfNew+X3+D**: Train은 full35보다 낮다(1% .751/.844, 3% .891/.886). Test 5%에서 Recall .766/.780, FPR .054/.024로 **seed 간 차이가 가장 작다(.014)**.
   mastra .622/.882를 잡지만 seed 10에서 canisterworm 41/68, rspack-vant 3/7로 mastra 제외 Recall이 .653으로 떨어진다. 3%에서는 seed 간 차가 .229로 크다.
3. **Test 일반화 목표(두 seed 모두 Recall ≥ .90, FPR ≤ .05)를 만족한 후보는 없다.** 가장 가까운 것은 full28_noObfNew 3%(.720/.949, FPR .020/.020)와 C5 5%(.757/.972, FPR .067/.046)다.
   모든 후보에서 seed 09의 mastra Recall이 .62 이하로 막힌다(fit에 mastra 유형이 거의 없음).
4. Train과 Test 순위가 계속 엇갈린다: Train 상위(full35_x3_d, B3)가 Test 하위이고, Test 상위(full28 계열, C5, gs24)가 Train 중하위다.
5. 결론: D06 Train으로 추가 Feature를 붙여도 mastra 유형 일반화는 풀리지 않는다. obfNew 제거가 여전히 유일한 레버이고, X3·D는 Train 내부 개선만 준다.
   D08 이후 데이터에 의존성 추가형 악성이 들어오기 전에는 이 차이를 Train에서 검증할 수 없다.
